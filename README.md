# Kids Games

Small reading, spelling and maths games for one or two children, hosted free on
GitHub Pages. Vanilla HTML/CSS/JS, no build step, no accounts, no analytics, no
network calls. Progress lives in `localStorage` on the device.

## Games

| Game | Skill | Status |
|---|---|---|
| Speak & Build | Spelling from speech, phonics levels 1-7 | live |
| Sight Word Splat | Dolch primer, then first grade | live |
| Rhyme & Swap | Word families, one letter at a time | live |
| Ten-Frame Fill | Making 10 and 20 | live |
| Fact Frenzy | Addition/subtraction to 20 | live |
| Array Builder | Multiplication as rows of dots | live |
| Number Line | Subtraction as movement, to 20 | live |
| Finish the Sentence | Read a sentence, choose the missing word | live |

Plus a **sticker shelf** (`stickers.html`): eleven milestones read straight off
the mastery store, per child, with a "new" badge until seen.

## Players

Each child gets their own profile: `kg.v2.<id>` holds their progress, `kg.players`
the roster, `kg.active` who is holding the device. Old single-store progress is
migrated to the first player created, not thrown away.

A game opened with nobody selected bounces to the picker rather than writing one
child's answers into another child's level. The grown-up page shows one child at
a time, and can rename, re-picture or delete them.

## Offline and installing

It is a PWA. `manifest.webmanifest` plus `sw.js` let it sit on a home screen and
run with no network:

- pages: network first, cache fallback (so a deploy shows up on the next visit)
- assets: cache first, network fill, keyed by the `?v=` URL
- audio: warmed once in the background (205 clips, ~640 KB) by `shared/pwa.js`,
  so the games work on a plane after a single visit

The service worker and the warm manifest are generated by
`dev/make-audio.py` / `dev/make-icons.js`; `shared/pwa.js` finds the site root
from its own script URL, so nothing hardcodes the repository name.

## The two hardest games

**Number Line** draws a fixed 0-20 line and marks the start. The answer buttons
sit under it; after an answer the travelled span lights up, so "12 − 5" is a
visible trip rather than a fact to recall.

**Finish the Sentence** shows a decodable sentence with one blank and speaks it
(the prompt is a recording, not a synthesiser). Every word in the sentence is
tappable and plays its own clip, so a stuck reader can hear the word instead of
guessing. The four options are all real words from the same vocabulary.

## How the learning works

`shared/learn.js` is the whole engine. Every game records each attempt against
one item (a word, a fact) in a Leitner box:

- correct -> box up, longer rest before it appears again
- wrong -> back to box 1, returns inside the same session
- box 4 = mastered, a few days off

`Learn.pick()` serves due reviews before new items, so time goes where the child
is actually weak. `Learn.adapt()` moves the difficulty: three right in a row
levels up, two wrong in a row levels down. No settings screen for a parent to
guess at.

Feedback never just buzzes. A wrong answer shows the correct spelling, reads it
aloud, and requeues the word. No timers, no lives, no game over.

## Adding a game

1. `games/<name>/index.html`
2. Include `../../shared/style.css`, `learn.js`, `speech.js`, and `words.js` if
   it needs word lists.
3. Call `Learn.pick(deck, pool, exclude)` for the next item,
   `Learn.record(deck, item, correct)` on every attempt, and
   `Learn.adapt(deck, correct, maxLevel)` after it.
4. Add a card to the hub in `index.html`.

## Speech

`shared/speech.js` wraps the built-in browser voices, so there are no audio
files to ship. iOS Safari only allows speech that starts inside a tap: the games
call `Speak.unlock()` from their first button, which is why there is a start
screen. If the browser has no voices, the game says so instead of presenting
dead buttons.

## Deploying

Pushed to the `main` branch, GitHub Pages serves the repo root. `.nojekyll` keeps
Jekyll from eating files that start with an underscore.

Pages caches assets for 10 minutes, so bump the `?v=` on the `shared/` links when
you change a shared file, or a browser will keep running the old engine.

## Testing
